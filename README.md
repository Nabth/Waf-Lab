# WAF Lab (OWASP Coraza + Juice Shop)

Лабораторный стенд для исследования WAF, отработки поиска ложных срабатываний (False Positive) и изучения механик обхода (WAF Evasion) на современных веб-приложениях.

## О проекте
Современные Single Page Applications (SPA) и REST API генерируют трафик, который WAF не всегда способен корректно интерпретировать без дополнительной настройки. Из-за отсутствия контекста приложение может ломаться: перестают работать фоновые запросы, авторизация или корзина. 

Этот стенд позволяет безопасно воспроизводить такие ситуации, анализировать логи и писать точечные исключения. В дальнейшем его можно использовать как полигон для исследования методов обхода WAF.

## Архитектура
- **WAF**: OWASP Coraza + OWASP CRS (через Caddy)
- **Мишень**: OWASP Juice Shop (уязвимое SPA)
- **Эмулятор**: Playwright (имитация действий реального пользователя)

## Кейсы ложных срабатываний (в этом репозитории)
В рамках исследования были воспроизведены и задокументированы 5 реальных кейсов:
1. **Socket.IO (WebSockets)**: WAF блокирует `POST /socket.io/` из-за `Content-Type: text/plain` (правило `920420`).
2. **Метод PUT (Корзина)**: WAF запрещает метод `PUT`, ломая процесс оформления заказа (правило `911100`).
3. **REST API Endpoint `whoami`**: WAF блокирует `GET /rest/user/whoami` из-за совпадения имени эндпоинта с Unix-командой (правило `932260` RCE).
4. **SQLi в поиске**: WAF блокирует поиск с апострофом (`apple'--`), принимая его за SQL-инъекцию (правило `942100`).
5. **Host Header IP**: WAF начисляет штрафные баллы за доступ по IP-адресу вместо домена (правило `920350`).

## Решение и Эволюция (Safe Tuning)
Вместо глобального отключения правил (`SecRuleRemoveById`) в проекте используются точечные исключения (`ctl:ruleRemoveTargetById`), которые отключают проверку конкретного параметра только для конкретного URL.

При настройке исключений важно не открыть дыру. В ходе исследования были пройдены два этапа:
1. **Наивное исключение (`ctl:ruleRemoveTargetById=942100;ARGS:q`)**: полностью отключило проверку SQLi для параметра поиска. Это починило ложное срабатывание, но пропустило реальную атаку.
2. **Безопасное исключение (с использованием `SecRule ... chain`)**: правило разрешает передачу спецсимволов, но **только если** в запросе нет явных SQL-паттернов (`UNION`, `SELECT`, `OR 1=1`).

В итоге:
- `GET /rest/products/search?q=apple'--` → Пропускается.
- `GET /rest/products/search?q=test OR 1=1` → Блокируется.

## Как запустить
1. Клонируйте репозиторий.
2. Запустите стенд:
   ```bash
   docker compose up -d
   ```
3. Интерфейс Juice Shop (за WAF) доступен по адресу: http://localhost:8080

## Как воспроизвести исследование 
1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   playwright install chromium
   ```
2. Запустите эмулятор пользователя:
   ```bash
   python emulation/user_emulator.py
   ```
3. Проверьте логи WAF на наличие блокировок:
   ```bash
   grep '"is_interrupted":true' logs/audit.log
   ```

## ⚠️  Дисклеймер
OWASP Juice Shop является намеренно уязвимым приложением. Данный стенд предназначен исключительно для образовательных целей и настройки WAF.
